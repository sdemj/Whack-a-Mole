# 게임 자가점검 킷

HTML 게임을 배포하기 전에 **직접 돌려서 문제를 찾는 도구**입니다.

찾아주는 것은 대체로 **혼자 테스트할 때는 잘 안 드러나는 것들**입니다.
내 컴퓨터에서는 멀쩡한데 서버에 올리면 깨지는 것, 오래 하면 느려지는 것,
화면을 나갔는데 뒤에서 계속 돌아가는 것 같은 문제입니다.

특정 게임을 겨냥한 것이 아니라 **어떤 HTML 게임에도 쓸 수 있는 일반 도구**입니다.
자유롭게 쓰시고, 필요에 맞게 고쳐 쓰셔도 됩니다. 다른 프로젝트에 가져가셔도 됩니다.

---

## 준비물

- **Node.js** — 파일 검사에만 필요합니다 ([nodejs.org](https://nodejs.org) 에서 LTS 버전)
- **크롬 브라우저** — 조작 검사에 필요합니다

**설치할 패키지는 없습니다.** `npm install` 안 해도 됩니다.

---

## 도구 1 — 파일 검사 `check-files.js`

게임 폴더를 훑어서 배포 후 문제가 될 만한 것을 찾습니다. 브라우저 없이 몇 초면 끝납니다.

```
node check-files.js [게임폴더경로]
```

예시:
```
node check-files.js ./my-game
node check-files.js C:\work\game
node check-files.js .
```

### 무엇을 봐주나

| 항목 | 왜 중요한가 |
|---|---|
| **파일명 대소문자** | `Korea.png` 를 찾는데 파일은 `korea.png` 인 경우. 윈도우·맥에서는 멀쩡히 보이지만 **리눅스 서버(GitHub Pages 등)에서는 안 보입니다.** 로컬 테스트로는 절대 발견 못 합니다 |
| **파일 이름 조합** | 코드가 데이터로 파일명을 만드는 경우(`` `${단어}.png` ``). 위 문제가 생기기 쉬운 구조라 알려줍니다 |
| **첫 로딩 용량** | 첫 화면에서 실제로 몇 MB를 받는지. 파일 안에 그림·소리를 넣어두면 재방문해도 매번 다시 받습니다 |
| **외부 서버 의존** | 글꼴·아이콘·스타일을 외부에서 받아오는 경우. **외부 접속이 막힌 망에서 화면이 깨집니다** |
| **타이머 정리** | `setTimeout` 은 쓰는데 `clearTimeout` 이 없으면, 화면을 나가도 예약된 작업이 남습니다 |
| **키보드 표시** | 키보드로 이동할 때 어디가 선택됐는지 보이는지 |
| **음성 읽기 방어** | 기기 음성 읽기(TTS)를 쓸 때, 목소리를 지정하지 않으면 다른 언어로 읽힐 수 있습니다. TTS를 안 쓰면 이 항목은 나오지 않습니다 |
| **중복 id** | 같은 id가 두 번 쓰이면 코드가 엉뚱한 요소를 집습니다 |

`[문제]` 는 배포하면 실제로 깨지는 것, `[확인]` 은 상황에 따라 문제가 되는 것입니다.

결과를 파일로 받고 싶으면:
```
JSON_OUT=result.json node check-files.js ./my-game
```

## 도구 2 — 조작 검사 `probe.js`

**게임을 실제로 해보면서** 뒤에서 무슨 일이 일어나는지 지켜봅니다.
게임 코드는 건드리지 않습니다. 새로고침하면 원래대로 돌아갑니다.

1. 크롬에서 게임을 엽니다
2. **F12** → **Console** 탭
3. `probe.js` 파일 내용을 **통째로 복사해 붙여넣고 Enter**
4. 게임을 평소처럼 해봅니다
5. Console 에 **`점검()`** 이라고 치고 Enter

### 이렇게 해보세요

문제는 대부분 **평범하지 않은 순서**로 조작할 때 드러납니다.
한 판을 곱게 끝내면 아무것도 안 나옵니다.

- 정답을 맞힌 **직후 바로** 나가기 버튼
- 기회를 다 쓴 팝업을 **닫지 않고** 나가기
- 팝업을 아래 버튼 대신 **X 로 닫기**
- 게임 중간에 처음으로 → 바로 다시 시작
- 한 판을 끝까지 하고 또 시작하기 (2~3회 반복)
- 터치 화면이라면 **손가락 두 개로 동시에** 만지기

### 무엇을 봐주나

| 항목 | 무슨 뜻인가 |
|---|---|
| **화면을 옮긴 뒤에도 실행된 예약** | 게임 화면에서 예약한 작업이 메뉴 화면에서 실행됐다는 뜻입니다. 나간 화면에서 소리가 나거나 진행이 저절로 넘어갑니다 |
| **취소되지 않은 반복 타이머** | 다시 시작할 때마다 쌓이면 시간이 두 배로 빨리 흐릅니다 |
| **이벤트 누적** | 화면을 다시 그릴 때 이전 것을 안 지우면 오래 쓸수록 느려집니다 |
| **겹쳐 있는 요소** | 손을 뗐는데 사라지지 않은 잔상 같은 것 |
| **음성 읽기** | 몇 번 울렸는지, **게임 화면이 아닌 곳에서 울렸는지** |
| **실행 중 오류** | 화면에는 안 보이지만 내부에서 난 오류 |

## 이 도구가 못 잡는 것

정직하게 적어둡니다. 아래는 사람이 직접 봐야 합니다.

- **내용의 옳고 그름** — 단어 뜻, 번역, 문장의 자연스러움, 힌트가 정답을 알려주는지
- **기획안대로 만들어졌는지** — 라운드 수, 문항 수, 단어 목록
- **재미와 난이도** — 아이가 실제로 할 만한지
- **실제 기기의 소리·터치 감각**
- **디자인** — 글자 크기, 색 대비, 배치

도구를 돌렸다고 점검이 끝난 것은 아닙니다.

---

## 결과를 어떻게 쓰나

`[문제]` 가 나오면 대부분 고쳐야 합니다.
`[확인]` 은 상황에 따라 다르니 판단이 필요합니다 — 예를 들어 외부 글꼴은
인터넷이 되는 환경에서만 쓴다면 괜찮습니다.

고친 뒤 **다시 돌려서 사라졌는지 확인**하는 용도로 쓰시면 가장 좋습니다.

---

## 고쳐 쓰기

두 파일 모두 라이브러리 없이 순수 자바스크립트로 되어 있어 그대로 읽고 고칠 수 있습니다.

- `check-files.js` — 검사 항목이 `── 1.` ~ `── 8.` 로 나뉘어 있습니다.
  필요 없는 항목은 지우고, 프로젝트 규칙에 맞는 검사를 추가하시면 됩니다.
- `probe.js` — 감시 대상이 타이머 / 이벤트 / 음성 / 오류로 나뉘어 있습니다.
  `점검()` 함수 안의 판단 기준(개수 임계값 등)을 프로젝트에 맞게 조정하시면 됩니다.

마음껏 쓰시고 고치셔도 됩니다.
